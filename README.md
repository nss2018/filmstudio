# 科普宣传片工坊

**浏览器里写乐谱、渲片子，配乐和画面同源。** 零安装、零后端、零第三方库——所有合成、渲染、编码都在浏览器里跑完，手机上打开就能用。

在线版：https://nss2018.github.io/filmstudio/

---

## 三件事

| | 干什么 | 适合谁 |
|---|---|---|
| 🎼 **音乐工厂** | 填一个主题，出一首不重复的配乐 | 不会作曲、只想拿到能用的旋律的人 |
| 🎹 **配乐台** | 图形钢琴卷帘 / cues.json 双向编辑，试听、导 wav | 想自己改的人 |
| 🎬 **宣传片生成器** | 2D 母题 或 **3D 生活场景**，填几段文案 → 出带配乐的视频 | 做科普短片、生活短片的人 |

## 0. 3D 生活场景引擎（WebGL2）

在「宣传片生成器」里把**画面引擎**切到 `3D 生活场景`，它做的事是：

**文案 →（导演）→ 分镜 →（WebGL）→ 画面**

### 生活场景库（20 个 3D，都是程序化几何，零素材）

| 批次 | 地点 |
|---|---|
| 第一批 | 咖啡馆 · 街道 · 公园 · 海边 · 书房 · 实验室 · 厨房 · 夜市 |
| 第二批 | 卧室 · 菜市场 · 地铁站台 · 校园 · 雨中街道 · 阳台天台 |
| 第三批 | **客厅 · 办公室 · 面包房 · 医院病房 · 田埂麦田 · 公交站** |

每个地点自带几何、灯光方案、雾参数、天空渐变、站位/坐位知识（角色该站哪、该坐哪）。
同一地点用固定种子生成 → **每次打开布局一致**（可复现），不同地点各不相同。

另有 **18 个 2D 插画场景**（`js/scene2d/`）与 3D 地点一一对位（第三批 6 个也补了 2D 版），
画面引擎切到「2D 生活场景」时用 Canvas2D 逐帧画，同样零素材、同样可复现。

### 人物 / 动物（7 个，关节层级 + 程序化动画）

人（站/走/坐/挥手）· 猫（走/坐/蹭）· 狗（跑/坐/摇尾）· 鸟（飞/停）· 鱼（游）· 兔（跳/坐）· 蝴蝶（飞）

造型走低多边形：几个基本体拼一起，靠**剪影和动作**认人认动物，不追求解剖。
动画全部由 `t` 算出（呼吸 / 行走相位 / 摆尾 / 扇翅 / 跳跃抛物线），**不用随机数** → 同一条分镜每次渲染完全一致，视频才可复现。

### 导演层：文案怎么变成分镜

**① 本地（默认，零 Key 不联网）**

关键词词典 + 曲式模板 + 种子 PRNG：

- 地点词典：咖啡/杯/吧台→咖啡馆，街/路/通勤→街道，实验/试剂/数据→实验室…
- 角色词典：猫/喵→猫，他/她/学生→人，蝶/翅膀→蝴蝶…
- 氛围词典：夜/晚/霓虹→夜晚，温暖/柔和/黄昏→暖调，冷/数据/精密→冷调
- **词越长越具体**：「实验室的夜」里 `实验`（权重 2）压过 `夜`（权重 1），所以判实验室而不是夜市
- 曲式：3 段 = 建立→推近→拉远；4 段加横移；5 段加环绕

**② AI 导演（要 Key，可写提示词）**

把本地初稿（主地点/主角/氛围/镜头序列）连同文案一起喂给模型，让它**在初稿基础上调整**，
输出结构化分镜 JSON。然后过一遍白名单校验：

- 地点 / 角色 / 动作 / 镜头 / 氛围都必须在合法表里 —— 模型编的 `mars_base`、`dragon`、`neon` 会被本地规则顶掉
- **站位坐标不信模型**，仍用本地点的站位知识重算（模型不知道椅子在哪）
- 段落数按文案对齐，多退少补

### 导演的判断力（这是「像那么回事」的关键，纯随机做不到）

- 鱼 / 蝴蝶 / 鸟不该出现在室内 → 换角色（保留地点）或换地点
- 室内只允许站/走/坐/挥手，不许跑/飞/跳/游
- 整片保留一个主角，不每段换人（否则叙事断裂）
- 换地点只切到「相关地点」（咖啡馆→街道/厨房/公园），30% 概率，不跳到另一个世界
- 角色走向镜头时会转身面向镜头，不会背对观众站着

### 不重复怎么做

- 种子 = `片名 + 全部文案` 的 hash → **同文案默认给同一部片子**（可复现）
- 点「🎲 换一版」换种子 → 地点走位、镜头、氛围都变，主角和叙事线不变
- 20 个种子实测给出 ≥12 套不同分镜

### 渲染

前向着色：4 盏点光的半兰伯特 + 边缘光 + 线性雾 + 色调分级（白天/黄昏/夜晚/暖调/冷调），
水面有波纹与高光，辉光走「阈值提取 → 高斯模糊 → 叠加」，最后加暗角。
几何是 flat shading（顶点不共享），棱角分明。

**为什么要两个 canvas**：GL 画布渲染完 `drawImage` 回 2D 的 `stage`，字幕叠在上面 ——
这样现有的 `stage.captureStream()` + MediaRecorder 导出链路**一行都不用改**，
录出来的就是带 3D 画面 + 字幕的成品。

### 3D 画质三档：线条轮廓 / 叠加 / 实体（默认线条轮廓）

不是「把实体调暗」，是**换一套着色器**：线框档走 `FS_LINE`（`js/gl/render.js`），
**不吃法线、不吃 4 盏点光、不吃雾的完整计算** —— 只用顶色 + 距离衰减 + 一点微光。
省掉的正是光照，所以才是「轻量」。

抽边在 `geom.edges()`（`js/gl/geom.js`），三个坑都踩过：

| 坑 | 现象 | 正解 |
|---|---|---|
| **按下标去重没用** | `tri()/quad()` 每面 push 一组全新顶点，立方体 12 条棱在 idx 里是 36 个不同顶点对 → 画出来是三倍亮度的粗线 + 斜面 z-fighting | 按**量化坐标**建规范顶点号再去重。量化 1e-4（最小构件也有 1e-2 量级，绝不会误并） |
| **只写深度会卡死** | 「单帧耗时 > 400ms 就拒」写在冒烟里，而 `while(true)` 根本不会返回 → 那句判断永远没机会执行 | 同步代码没法在运行期打断自己，防线必须提前到**静态检查** |
| **不画暗面 = 一团毛线** | 纯线框如果真的一次面都不提交，深度缓冲是空的 → 所有背面的边全透出来（出图确认） | 线框档仍画一遍面，但走 `FS_LINE` 的 `uFill` 分支，片元里**直接 return**，只写深度不上色 |

折痕过滤（`creaseAngle: 18`）：`quad` 拆成两个三角后中间那条**对角线**也会被描出来，
在大片地板/墙面上 criss-cross 一片，像毛线不像线稿。判据是「这条边两侧的面法线夹角
小于阈值 = 共面 = 三角化线 → 剔掉」，盒子真正的 90° 棱会留下。
实测客厅场景 1193 → 728 线段，干净的建筑线稿感。

- 描边网格**懒建**（`m.line !== undefined`）：抽边是纯 CPU 的 O(三角形) 遍历 + 哈希去重，
  20 个场景全预建在低端机上会卡一下，而大多数人只用一档。建过一次就缓存，来回切不重算。
- 描边网格也进 `disposeAll` 释放显存（显存不是 JS 对象，光 delete 是放不掉的）。
- 描边与实体**共用同一份 `castPose`** 世界变换 —— 两条通道各算一遍必然错位。
- 画质档位进 `filmSnapshot`（导出用 snap 不用 film），否则「预览线框、导出实体」。

⚠️ 顶栏环境自检里会显示 `3D 生活场景 可用/无 WebGL`。没有 WebGL 的环境（老 Safari、
虚拟机、禁了硬件加速）切 3D 会看到一句人话错误，2D 母题照常可用。

## 1. 音乐工厂

**填个主题（比如「群论」「量子」「热血少年」「咖啡猫」），点生成，出来一首完整的配乐。**

它不是纯随机（纯随机 = 白噪音），也不是照抄（照抄 = 侵权 + 一耳朵听出来）。做法是音乐学里最朴素那一套：**母动机 + 变形 + 曲式 + 和声约束**。

### 采集：先从素材库里拿

| 素材 | 数量 | 例子 |
|---|---|---|
| 母动机 | 12 | 固定低音型下行（帕赫贝尔型）、圣咏式级进、八度跳进（摇滚型）、大波浪、探戈切分… |
| 和声进行 | 14 | I–vi–IV–V、i–VI–III–VII、i–iv–V–i、I–IV–iii–I… |
| 鼓 pattern | 14 | 8 分网格的 kick / hat / snare 组合 |
| 风格谱面 | 7 | 科技科普 / 古典讲义 / 热血开场 / 空镜留白 / 俏皮律动 / 节奏推进 / 纪录片 |
| 音阶调式 | 7 | 大调五声、小调五声、自然大/小调、多利亚、利底亚、混合利底亚 |
| 织体 | 12 音色 | lead + bass + pad + arp 的组合，每个风格有自己的搭配 |

### 创新：再用 9 种变形算子重组

逆序 · 级数上移/下移 · 倒影 · 高八度 · 节奏拉长 · 节奏收紧 · 加经过音 · 挖气口 · 换动机尾

每个乐句抽 1–2 个算子，得到一个「乐句变体」；**变体签名会进集合查重**，同一首里不出现同样的乐句（最多试 14 次，重抽不出来才允许微重复）。

### 两条让它「不跑调」的规则

1. **强拍吸附**：整数拍上的音强制吸附到当前和弦的音（`nearest` 取最近的和弦音）。
2. **弱拍可走经过音**：弱拍有 45% 概率走向邻近的经过音，让旋律不呆板。

> ⚠️ 这里有个容易写错的地方：**别再给小调三度「减半音」**。小调音阶的级数本身已经含小三度（natural minor 的 `deg+2` = +3 半音），再减 1 就把 i 和弦的 C–E♭ 变成 C–D（大二度）——那是教科书级跑调。测试里有一条断言专门守这个。

### 怎么保证「不同、不重复」

- **同主题 + 同种子 → 逐字节相同**（mulberry32 + FNV-1a，不用 `Math.random`）
- **换种子 → 必换一首**（实测同主题 30 个种子 = 30 首不同）
- **不同主题 → 风格/调式/BPM/动机/鼓型全不同**（中文关键词库命中 + hash 兜底）
- **连点「再来一首」也不重复**：每首曲子算一个 8 位指纹（`fingerprint`），生成前先避开已出过的指纹
- 指纹还会显示在界面上，方便你记「哪首是哪首」

### 主题词是怎么判风格的

内置中文关键词表，比如：

- 群 / 对称 / 结构 / 数学 / 几何 / 证明 / 公理 / 拓扑 / 代数 → 科技科普 · 古典讲义
- 量子 / 宇宙 / AI / 算法 / 赛博 / 神经 / 基因 → 科技科普 · 纪录片
- 热血 / 励志 / 少年 / 梦想 / 挑战 → 热血开场 · 节奏推进
- 诗 / 梦 / 夜 / 海 / 月光 / 远方 → 空镜留白 · 纪录片
- 可爱 / 猫 / 咖啡 / 游戏 / 甜 → 俏皮律动 · 节奏推进

命中后 7 成概率给第一个（更专属的那个），否则在候选里挑；一个都没命中就按 hash 落表——**稳定可复现**，不会这次给你科技下次给你民谣。

生成的界面上会写清这首曲子**采了什么、怎么改的**（动机 / 和声 / 调式 / 织体 / 鼓型 + 用到的变形算子 + 指纹）。

## 2. 配乐台

### 图形钢琴卷帘

- 点空格子放一个音，**按住拖过去会连成一条**；拖音符换位置，拖它右端改时长
- **右键**或**长按**删除（手机上没右键，用长按 + 震动）
- 纵轴是五声音阶（两个八度 10 格）——**怎么点都不难听**，给非乐手用
- 右侧轨列表可改乐器 / 音量 / 加轨 / 删轨
- 图形和源码是同一份数据：图形里画的音，切到「源码」就是标准 cues.json

### cues.json 规范

```json
{
  "bpm": 84,
  "tracks": [
    { "name": "pad",   "instrument": "pad",  "notes": [{"p": "C3", "t": 0, "d": 2}] },
    { "name": "drums", "instrument": "kick", "loop": 1.0, "notes": ["x","-","x","-"] }
  ]
}
```

- `p` 音名（C4 / F#2 / Bb3），`t` 起始**秒**，`d` 时长**秒**
- 拍号写法：`{"p":"C4","beat":4}` 或 `{"p":"C4","beats":4}`（跟秒可以混用）
- `loop` 给**秒数**，整轨按这个周期反复铺（游戏 BGM 不用写满整首）
- 打击乐数组：`"x"` 敲一下、`"-"` 空一拍；字符串 `"notes": "x - x -"` 也认
- 解析错误都带位置和人话，例如 `tracks[0].notes[0] 音名 "H9" 不合法（例：C4、F#2、Bb3）`

12 种音色：`pad / organ / pluck / bass / lead / blip / bell / click / kick / snare / hat / clap`。
导出是 16-bit PCM wav，可直接剪进任何视频软件。

## 3. 宣传片生成器

### 一键成片（联网全自动）

文案 tab 最左边那个「⚡ 一键成片」：**一个字都不用填**，点一下就出片。

联网时（「API 设置」里填了 Key 就行，Key 只存你自己浏览器），一个来回让模型把

> 主题 → 具象例子 → 片名 → 每段字幕 → 每段分镜（地点/角色/镜头/氛围）

全部吐出来，本地只做白名单校验和走位重算，然后**直接开导出**。原来的三步
「生成文案 → 按文案生成分镜 → 导出」全都能省。

两个设计取舍值得说：

- **没 Key 时宁可报错，也不偷偷回落到本地模板。** 否则你会以为片子是 AI 出的，
  其实渲染的是上一次的旧文案——那种"看起来能跑但内容不对"比直接报错糟糕得多。
- **模型和文案在同一份输出里。** 以前是两次请求，第二个请求看不见第一个写了啥，
  分镜容易和字幕拧着；现在一次给全，模型同时看得见字幕和目标画面。

模型说中文地名（便利店 / 大排档 / 菜場）也能认——见 `director.js` 的 `PLACE_ALIAS`，
20 个地点各带简繁体 alias，`resolvePlace()` 负责翻译；翻译不出来的交回本地白名单顶。

手动通道照旧可用（主题、具象例子、生成文案、AI 导演），一键成片只是把它们串成一条。

---

填几段内容 → 选一个视觉母题 → 导出视频（**画面和配乐在同一个文件里**）。

| 母题 | 长什么样 |
|---|---|
| 概念递进 | 同心圆扩散 + 标题浮入、句子一行行展开 |
| 公式推导 | 公式逐字揭示，未揭示的是暗色，光标跟着走 |
| 数据演进 | 每段落一根柱子从零长到目标值 |
| 对比演示 | 左右分屏，中缝线随进度推进；标题写 `A vs B` 就会 split |
| 几何演化 | 多边形按段数展开旋转，顶点带辐条（对称群的画法） |

四个配色：墨蓝 / 暖橙 / 薄荷 / 纯黑白。`BPM` 和「每段拍数」决定节奏——**时长不用手填**，按段落自动排开。字幕开关在「2. 定节奏」里，字幕会按字数自动缩号，长句不会溢出画面。

### 文案助手（字幕从哪来）

- **本地模板**（默认，不联网、不要 Key）：按「主题 + 风格（科普/热血/俏皮/诗性）+ 段数」拼出片名和每段字幕，同主题每次一样，方便反复调
- **AI 通道**：填 Base / Key / 模型，走 OpenAI 兼容的 `/chat/completions`。两种走法：
  **① 走本站 `ai.php` 代理（下拉第一项，豆包就用这个）** —— Base 填 `ai.php`，请求先到本站服务器、由它转发给上游。
  火山方舟**明令禁止浏览器直连**（`/api/v3/models` 连 `Access-Control-Allow-Origin` 都不返回，实测 401 且无该头），
  纯静态页直连必被浏览器按 CORS 拦死，模型名填得再对也没用。Key 只存在浏览器 localStorage，
  随请求转发一次即弃，**服务器不落盘、不写日志**；只放行白名单 host（防止这台机器变成万能开放代理），
  并按单 IP 每分钟 40 次限流（防被当免费额度刷）。
  **② 浏览器直连**（DeepSeek / OpenAI / 硅基流动 / Moonshot / 自建）—— 不过本站服务器，Key 只进 localStorage
- **「模型」那个框是个下拉**：填完 Key（或切到某个服务商）会自动拉一次 `/models`，把这个 Key 已开通的模型、控制台建的接入点（`ep-…`）全列出来，中文备注直接显示（豆包 Seed 2.0 / DeepSeek R1 / 自建接入点…），点一下就填；你现在手上的模型名不会被顶掉，空着才自动选第一个。清单只存本机 7 天，离线也能选
- 万一某个服务（非豆包）也不给跨域，再退到老办法：把 `workers/proxy.js` 贴到一个 Cloudflare Worker，Base 填 worker 地址
- **报错一定带上游原话 + 下一步**（`script.js` 的 `upstreamMsg` / `denyTip`，纯函数、可测）：401/403 不再只说「检查 Key 和 base」，而是把网关返回的 `error.code` / `error.message` 挖出来，再按服务商给具体指引
- **方舟 401 就三条**：① Key 要取「API Key 管理」里那串（控制台「密钥管理」的 `AKLT` 密钥是 HMAC 签名的，Bearer 不认，必 401）；② Base 必须是 `https://ark.cn-beijing.volces.com/api/v3`（不是 `/v1`）；③ 模型要这个账号开通过的模型或自建的 `ep-` 推理接入点——方舟按账号授权，模型名写对但没开通照样 401。预设里那个 `doubao-seed-2-0-code-preview-*` 预览模型不一定人人有，切预设时若查到清单里有 `ep-` 接入点会自动换成它；模型框空着时自动选也优先 `ep-`。清单能拉到就重拉一次（一键成片 / AI 导演撞到鉴权错误会自动帮你重拉）
- 「给个每段拍数建议」会按最长一段的字数算一个不撞帧的拍数

### 配乐从哪来

- 默认：按**片名当主题**调音乐工厂生成（同一个片名可复现，不同片名必不同）
- 「🎼 按片名现生成一首」：当场换一首新的，并把它灌回配乐台（能看能改）
- 「🎬 拿去配宣传片」：在配乐台挑好的一首直接指定给这部片子

### 配乐跟文案走（`js/scoresync.js`）

有文案时，配乐不再自己响，而是**按字幕断句打点**：

- 每段文案按中文标点断句（超过 14 字再按 7 字切一刀），小句按字数比例铺在段落时长里，
  往右挪 5% 就是它的「落点」——字刚冒出来的那一帧就该有声音顶上来
- 对齐做两件事：原有的音符往最近的落点上吸附（半拍以内才挪，超过就不动，不拆曲子），
  再叠一条**「字幕打点」轨**，每句字幕一出现就给一记重音（原谱里有鼓就用鼓，没有就用 blip）
- 判「合拍」看两个数：**cov**（落点处有没有声音在响，和声/长音/循环都算）和
  **prox**（落点到最近起音的距离）。大片地方哑着、或断断续续还整体错开 → **直接不配乐**，
  只剩画面 + 配音，并在「配乐来源」那行写清楚为什么不配。
  一路都响着的铺底（cov ≥ 0.9）不追究起音——那叫和声，不叫脱拍
- 判不合拍时「只导配乐」也一起拦住，不会给你一个 0 秒的 wav

### 成片声音：四档（默认纯音乐）

「要不要人声」和「用哪个嗓子」是两件事，以前混在一个下拉里（不配音 = 音色选「无」），
结果**「纯音乐」这件事在界面上根本表达不出来**。现在拆开：

| 档 | 字幕 | 人声 | 配乐 | 什么时候用 |
|---|---|---|---|---|
| **纯音乐**（默认） | 显示 | 无 | 有 | 生活短片，字幕自己读，最耐看 |
| 人声 + 配乐 | 显示 | 有 | 有 | 讲解、知识向 |
| 纯人声 | 显示 | 有 | 无 | 只要旁白，不要背景干扰 |
| 全静音 | 显示 | 无 | 无 | 纯画面（自己配乐） |

- 选「纯人声 / 全静音」时会把「自动生成配乐」的勾**自动去掉** —— 界面上勾着、结果成片里
  没有，比不勾更让人困惑。
- 「只导配乐」按钮**无视档位**（显式要曲子，即使档位是纯人声也给），否则用户会以为按钮坏了。

#### ⚠️ 「没有背景音乐」的两个真实原因（2026-10-05 修）

用户反馈默认档听不到背景音乐。查下来是**两个独立的坑**，都不是"用户没操作对"：

1. **`copyAnchors` 只读 `s.text`，不读 `s.title`**
   → 「每段填了小标题、字幕框空着」（极常见，尤其用 AI 生成时）会得到 **0 个落点**
   → `use=false` → 报「这部片子没有文案」→ **整部片子一点声音都没有**。
   ⚠️ 这不是「用户没填内容」—— 他明明填了，标题就是内容。
   正解：`text` 为空就退回用 `title`。
2. **真的一句文案都没有时直接判 `use=false`**
   → 导出个哑片。正解：按**每段中点**兜底对齐（`fallbackBeats`），
   仍然按「声音够不够满」判 use；只有时间轴都不足半秒才真的没救。
   状态行会明说「还没填字幕，先按每段的节奏配乐」—— 不说的话用户会以为
   「配乐跟着字幕走」这个卖点没生效。

### 配音（人声念文案）

- 音色下拉：云希·男 / 晓晓·女 / 云扬·播音 / 晓伊·亲和（**选不选人声由上面的四档决定**）。
- 走服务器上的 `tts.php?voice=&text=`（edge-tts，48kbps 单声道 mp3），单段限 90 字。
  **`tts.php` 和 `ai.php` 是本项目仅有的两个需要 PHP 的文件**（其余全是纯静态）——
  部署到别处时必须把它们一起传上去，
  且服务器要有 `python3.8 -m edge_tts`；缺了会明确提示「服务器上没有 tts.php」，
  而不是静默地没声。
- 逐段容错：某段合成失败不会拖垮整条链，成功的照常排程，失败数与原因写进状态行。
- 预览与导出共用同一份 `narrCache`（`voice|text` → AudioBuffer），所以试听过的文案导出时不用再等。

### 2D 生活场景（`daily` 母题）

- 这个母题以前**根本不画字幕**，于是生活场景片导出后只有插画没有字；现在走公共 `sub()`
  （自动折行 + 超长缩字号 + 受「字幕」开关控制 + 逐字入场，见 `js/type.js`）。
- **光线闸门**：文案说「深夜 / 台灯 / 凌晨」时，不会给绿树蓝天的**大白天公园**
  （以前无地点词的段落按 hash 落表，实测「深夜的书桌」→ 公园，一眼假）。
  注意这条只拦「落表」，文案明说「深夜的公园」时仍然给公园。

#### 场景怎么选（2026-10-05 重做）

用户看着界面问：「上面也有下面也有，这有什么关系」+「你说几种，有p用」。
现场是三处在说同一件事：母题下拉写着「生活场景（2D 插画 · **18 种**）」，
它下面又有场景下拉显示同一个名字，再下面还有一整串
「AI·对称… → AI·对称… → AI·对称… → AI·对称…」。重做成各管一件：

| 控件 | 只管什么 |
|---|---|
| 母题下拉 | **画法**（概念递进 / 公式推导 / … / 生活场景），全片统一。不再报「18 种」——那是内部实现细节 |
| 每段一个卡片 | 一眼看全各段是什么场景、AI 画的带 `AI` 角标。**点卡片 = 选中那段** |
| 场景下拉 | **只改当前选中那段** |

⚠️ 三个实测踩到的坑：

- **改一次场景把 4 段全设成同一个**（就是用户截图里 4 段全变 AI 场景的原因）：
  原来是 `film.scenes2d = film.scenes.map(() => manual)`。母题才是全片统一的，
  场景是**逐段**的 —— 这两者的作用域搞混了。
- **`applyScenes` 整份重算**，任何一次改文案都把手动指定与 AI 场景冲掉。
  现在只在「段数对不上」时才对齐长度。
- **`aiClear` 把 `scenes2d` 置 null** 同样触发整份重算，把用户手动选的也一起冲掉。
  现在逐段换回自动选景。
- AI 场景是**注册进 `FS.s2dScenes`** 的，所以**切段时也要重建下拉** ——
  只在 `aiPaint` 成功时重建的话，「换个模型再画一段」画出来的场景在下拉里根本看不到。

### 让 AI 直接画这段（`js/aiscene.js`）

「取材智能化」分两层：词典决定**在哪个场景里画**，AI 决定**这个场景长什么样**。
选一段 → 点「让 AI 画这段」→ 模型按文案写一段 `f(g,t,p)` 的 Canvas2D 绘制代码 →
沙箱校验通过后注册进 `FS.s2dScenes`，**与手写场景走同一条时间轴**（导出/预览不用改一行）。

- **画笔限定**：只给模型 18 个原语（`sky / glow / groundGrid / building / tree / personSil /
  particles / text …`）的**真实签名**，不写任意代码。
- **静态检查（`lint`）拦死循环**：一律拒 `while` / `do`、拒 `for(;;)` / `for(;true;)` /
  条件变量永不改变、拒 `eval` / `new Function`。
  ⚠️ 这里踩过一个很贵的坑：最初把「单帧耗时 > 400ms 就拒」写在冒烟里，
  而 `while(true)` **根本不会返回** —— 那句判断永远没机会执行，node 进程被卡死 120s。
  同步代码没法在运行期打断自己，防线必须提前到静态检查。
- **冒烟**：在只记几何的假画布上真跑一帧。画不出东西（调用数 < 3）、引用不存在的画笔、
  单帧画超过 2 万次，都会被拒。
- **失败一律退回手写场景**（`unregister` + 保留原 `scenes2d`），并说清为什么 ——
  绝不黑屏。「清除 AI 场景」可一键全部撤回。
- 画笔清单有**防漂移守卫**（测试里逐个参数名回 `core.js` grep）。
  第一版手写清单错了 6 处（`building.windows/winCols`、`particles.x0/y0/x1/y1`、
  `groundBand.hz/y0/y1`、`catSil.s`、`cup.steam`），是出图后肉眼发现的
  —— 楼画出来了但一扇窗都没亮、粒子撒到画布外。

### 模型返回的 JSON 坏了怎么办（`js/script.js` 的 `repairJson`）

用户看到的是：`✗ Expected ',' or '}' after property value in JSON at position 331
（没动你已经填的内容，改好再试一次）`。两个问题：把责任推给用户（**他什么都没填错**），
以及抛的是 V8 原始英文报错，`position 331` 毫无可操作性。

模型吐坏 JSON 是**常态**。`repairJson` 用**一次线性扫描**修这些：

| 坏法 | 例子 |
|---|---|
| 尾逗号 | `{"a":1,}` |
| 单引号 | `{'a':'x'}`（键和值都修） |
| 裸键名 | `{a:1}` |
| 值里有真换行 | `{"a":"第一行⏎第二行"}` |
| 全角引号 / 全角冒号 | `{“a”：“x”}` |
| scenes 写成字符串数组 | `{"scenes":["一句"]}` |
| scenes 用了别名 | `segments` / `list` / `items` |

⚠️ **第一版用一串正则去修，结果只修好了键、没修好单引号的「值」**
（`{"title":'对称'}` 还是非法）。原因：正则分不清「引号里的内容」和「结构符号」，
一步改动了引号数量，后面所有正则就全错位了。
→ 正解是**逐字符判断自己在字符串内还是结构区**。

修不动才报错，而且报的是人话：坏在第几个字符附近 + 「不是你的问题」+ 下一步。

### 文字：`js/type.js`（仿全代码动画的排版语言）

那种片子的文字之所以「像样」，靠的不是字体，是**排版动作**。这一层把它收成零件：

| 零件 | 作用 |
|---|---|
| `revealText` | 逐字错开入场，每字从下方滑上来。`stagger` **按字数自适应**（写死 0.045 时 20 字字幕要 1.24 拍才出完，段尾还没读完就淡出了） |
| `subtitle` | 自动折行 → 最多两行（超了缩字号）→ 托底暗带（带高按行数算，不再一律 230px 吃掉一块画面）→ 关键词点亮 |
| `kicker` | 段首小标签：等宽 + 0.3em 字距 + 左侧生长短横线。默认**文字色 + 暗色投影**（主色在浅色场景上是「青字压浅蓝」，读不出来） |
| `title` | 大字重 + 逐字入场 + 随 p 横向生长的下划线 |
| `keywords` | 从书名号 / 数字 / 英文缩写里抽 2~3 个高亮词。刻意不引分词库 —— 错漏的代价只是「某个词没被点亮」 |
| `hitRanges` | 关键词在行内的区间，重叠会合并（否则同一段底色画两遍） |

⚠️ 逐字入场之后，一句话会变成 N 次 `fillText`（每次一个字）。
**「整句一次出现」那种老断言从 2026-10-05 起全部失效** —— 测试里改用 `hasText()`
（既能认整句一次填，也能把逐字序列拼回来再认）。

⚠️ 开场 1.4 秒的片名题头**会把母题字幕压掉**（`openingTitle` 闸门）。
这半句以前只写在注释里、代码没做 —— 截图里「城市的一天」正好骑在字幕上
（题头 H-34、daily 字幕 H-72，只差 38px 而字号 34）。

### 2D 母题的动画层（六个母题都不许「定格」）

原来六个母题整段的画面变化只有 **2.0%~4.9%**（实测 concept 2.2 / formula 1.9 / bars 2.8 /
split 4.9 / geo 3.0 / daily 2.0），观感就是「一张静态图挂一行字」。现在每个母题都叠一层
**运动基元**（`js/story.js` 顶部），全部是 `t` / `p` 的纯函数——导出仍然是逐帧确定性的：

| 基元 | 干什么 |
|---|---|
| `particles` | 自下而上飘的粒子（数量随段内进度长），给整段垫一层底噪 |
| `dial` | 环形仪表：底盘刻度按 `rpm` 持续自转 + 进度弧随 `p` 生长带发光 |
| `runner` | 光点沿一条线往返（`ping`），三个相位错开 → 构图一直不对称地动 |
| `spin` / `seg` | 持续旋转弧度 / 循环分段（`loop` 单程、`ping` 往返） |

各母题叠的法子：concept 光点绕场 + 同心圆弹性弹出 + 两侧卡片滑入；formula 粒子 + 侧边仪表 +
逐字揭示；bars 柱生长 + 粒子；split 分屏缝弹性推进；geo 多层环反向自转 + 中心脉冲；
daily 前景粒子 + 底部光带横向推移。

**修掉的三处「元素互相压」**（都是几何重叠，在缩略图上很容易漏看）：

1. **formula 标题与字幕重叠** —— 字幕原来在 `cy+118`，两行时上沿正好压住还在逐字揭示的公式；
   改到 `cy+172` 并要求揭示过半才淡入。另外夹中文的长公式（如「E = mc² 的秘密」）按 64px 量
   会横着顶出 1280 的画面，现在**超宽就按比例缩字号**（下限 30px）再重量一次。
2. **split 字幕被色板盖住** —— 色板底边原来落在 y=610，字幕基线 612（两行时上沿 579.5），
   正好骑在色块边上；色板收 60px（底边 580）+ 字幕下移 24px（`H-84`），两行时留 23px 净空。
3. **geo 标题被多边形扫到** —— 多边形是**旋转**的，R 长到 280 时顶点最高点 y = 360−280 = 80，
   扎进标题带（63~105）和分隔线（118）。R 上限收到 210（`110 + 100*grow`）：
   顶点最高只到 150、最低到 570（字幕上沿 594），两头都不碰。

这三处现在有**几何回归测试**兜着（`tests/node-test.js` 第 18 节）：用一个记录位置/字号/矩形的
spy ctx 真量文字矩形、色板底边与顶点坐标，断言「字幕最高点 > 色板底」「顶点最高 > 标题底」
这类不变量，比肉眼盯缩略图可靠。⚠️ 写这节时踩了个坑：`stubCtx` 的 `save/restore` 原来是
`noop`，于是 `particles` 改完 `globalAlpha` 后再没恢复，后面所有 `fillText` 都读到一个被污染的
alpha（实测 0.077），断言全被过滤空了。**现在 stub 的 `save/restore` 是真实现**（维护一个栈），
顺带能抓到「运动基元忘记配对 save/restore」这类真 bug——那在真机上表现为整块画面发灰。

### 导出

- **视频（含配乐）**：`canvas.captureStream` + `MediaStreamDestination` 一起录进 MediaRecorder，音画共用一套时钟，不会各走各的
- **只导配乐**：wav
- **逐帧 PNG**：每段中点一张
- **项目备份**：JSON，可以把整个片子（含自定义配乐）存下来

**逐帧确定性**：导出时画面时间 `t = k / 30`（k 是帧号），墙钟只用来决定「什么时候推下一帧」，
不参与画面计算。好处是同一份片子两次导出画面完全一致，掉帧/卡顿也不会让时间轴跳变。
浏览器不支持 `requestFrame`（手动推帧）时自动回落成「自动抓帧 + 同样的 t=k/30」，提示栏会写明当前是哪种模式。
导出前会对 `film` 做一次快照，导出期间改界面不会让成片串帧。

## 一个 CSS 陷阱：`hidden` 属性被 `display` 盖掉

用户截图里「画面引擎 = 2D」但「3D 画质」那行照样显示。原因：

```css
label{…display:flex}          /* 元素选择器 */
.fl{…display:block}           /* 类选择器 */
[hidden]{display:none}        /* UA 样式表里，优先级最低 */
```

`hidden` 属性本身只是 UA 样式表里的一条 `display:none`，
**任何自带 `display` 的类/元素选择器都能盖掉它**。
受影响的不是那一行，而是**所有用 `hidden` 控制的行**（3D 导演面板、场景面板、字幕时间码…）。

修法是全局一条（`css/app.css`）：

```css
[hidden]{display:none !important}
```

`!important` 在这里是唯一该用的场合 —— 它要压的正是「别的选择器自带 display」这类冲突。

## 借鉴 digiCreature_ios（光孢）的三条做法

同机器上的另一个项目 `/Users/nie/Desktop/WeChatProjects/digiCreature_ios` 用
**CoreGraphics 2D + 手写 3D 数学**做数字生物渲染（没用 Metal/SceneKit，理由写在
`Render/CreatureRenderer.swift:7-11`：小程序端先在 2D canvas 上验证通了，iOS 端平移同一套算法，
好让「画面对」和「好看」的责任能分离）。它有三条做法我直接搬了过来：

| 做法 | 它怎么做的 | 我怎么用的 |
|---|---|---|
| **逐帧确定性** | `CreatureRenderer.frameRotY(base:k:fps:)`：姿态只由帧号决定，「不许读系统时间」，否则同一只生物导出两次会得到两段不同的动画 | 导出循环从墙钟驱动改成 `t = k/fps`，`captureStream(0)` + `requestFrame()` 手动推帧；导出前快照参数防串帧 |
| **有界缓存 + 淘汰时释放** | `boxCache` 超 256 条就清空，`NSLock` 保护，key 要量化（浮点 key 永不相等） | `js/gl/lru.js`：LRU 上限（场景 6 / 角色 8），淘汰时 `deleteVertexArray` + `deleteBuffer`——**光删 JS 对象不释放显存** |
| **显示与导出共用同一个 draw 入口** | 屏幕 `UIView.draw(_:)`、导出 `AVAssetWriter` 逐帧、离屏出图 `swiftc`，三条路都调同一个 `CreatureRenderer.draw`；背景也画在渲染层里，「导出时没有外层」 | 预览和导出都走 `engine.drawAt(t, ctx)`；GL 帧先 `drawImage` 回 2D 的 `stage` 再叠字幕，所以录出来就是带字幕的成品 |

另外它的两条「教训型」做法我也记下了：

- **`default` 分支是「枚举加了、渲染层没加」的完美掩护** —— 编译通过、运行不崩、只是那只生物画不出来。
  所以我的导演层用**白名单校验**代替兜底默认值：LLM 给了非法地点/角色一律顶掉并提示，不静默通过。
- **容差要比噪声大 16 倍、但比真实错误小 10⁷ 倍**（它做跨端逐位对拍时定的）。
  我这边没有跨端需求，但同一个原则用在了「沙盒里 Chrome 跑不动 WebGL」这件事上：
  与其猜 shader 能不能编译，不如给用户一个自检页，让结论来自真实像素采样。

它还有一条我没抄但值得记的：**「整个生物 = 一串球」**这个抽象（形变/遮挡排序/伪光照全作用在球上，
60+ 支形态共享同一套绘制代码），以及配套的「球面不接触就二分加密补球」修串珠身。
我的角色是 box/cylinder 关节层级，不存在这个问题，但这个抽象对我下一步做「可参数化的生物」
（比如把 `cast.js` 扩成细胞/机械体）是同一思路。

## 已知限制

- 音乐工厂只判**和声与结构**，不判审美：调式内 + 强拍合规 ≠ 好听
- 素材库是内置的公有领域风格动机，**不是真的在听你给的歌**；想扩语料直接改 `js/factory.js` 里的 `MOTIFS` / `PROGS` / `PATTERNS`
- 工厂生成不联网、也没有版权问题（素材是程式化的通用语汇）；要「像某首歌」请别用
- 只判画面不判**审美**：节奏拖沓、配色难看它不管
- 字幕按段内固定行排，不做逐词断句
- 导出视频走浏览器编解码器，码率和帧率跟平台有关；长片（>2 分钟）建议分段导出再接
